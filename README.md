# Friday

A research notebook. One entry a day: what you planned, read, learned, thought,
built and wrote — kept in a Google Sheet you own, and readable back later.

Runs on the web, iOS and Android from one codebase.

---

## The name

Friday is the one who keeps the record and does the legwork. Borrowed three
times over: the reanimated assistant in Project Itoh's *Empire of Corpses*,
Crusoe's companion on the island, and Stark's AI after JARVIS.

The internal identifiers still say `myresearchnotebook` — bundle id, Expo slug,
deep-link scheme. That is deliberate: changing an Android package makes an
installed build a *different app* that will not update in place. See
[ADR-006](docs/DECISIONS.md).

## How it works

```
 Expo app (web · iOS · Android)
        │
        ├── web ──▶ Netlify Function /api/proxy ──▶ Apps Script ──▶ Google Sheet
        │            verifies Firebase ID token
        │
        └── native ─────────────────────────────▶ Apps Script ──▶ Google Sheet
                                                   ⚠ see Known issues
```

- **Auth** — Firebase Email/Password. Accounts are created by hand in the
  Firebase console; there is no sign-up path in the app.
- **Storage** — a Google Sheet, reached through an Apps Script web app. No
  server of ours holds your notes.
- **Web requests** — proxied through a Netlify Function that verifies the
  caller's Firebase ID token before forwarding, which also solves CORS.

### The app itself

- **One page per entry.** Reading and writing are the same page — press Edit, or
  click any field, and type.
- **No Save button.** Edits debounce, coalesce into one write, and flush when you
  navigate away or close the tab. The bar reports what the save is doing.
- **Markdown everywhere.** Read mode renders it, write mode shows the source.
  Pasted URLs condense to numbered links.
- **A list you can scan.** Each entry shows one labelled line per filled field,
  grouped by month.
- **Search across everything** — ⌘K. TF-IDF over the full text of every field,
  with stemming, so "compress" finds "compression". Quote a `"phrase"` to
  require it verbatim. Results show the field and the passage that matched.
- **Light and dark**, following the system or pinned by the toggle in the bar.

## Setup

### Prerequisites

- Node.js 18+
- A Google account (for the Sheet and Apps Script)
- A Firebase project

### 1. Install

```bash
git clone <your-repo-url>
cd MyResearchNotebook
npm install
```

### 2. Google Sheet

Create a sheet with a tab named **`ResearchLogs`** and these headers in row 1,
in any order:

| Column | Meaning |
|---|---|
| `id` | UUID, generated by the client |
| `created_by` | author's email, from the signed-in user |
| `date` | the day the entry is about, and the time it was started |
| `plan_to_read` | what you planned to read |
| `plan_to_do` | what you planned to do |
| `did_read` | what you read |
| `learned_today` | what you learned |
| `new_thoughts` | what you thought of |
| `coded_today` | what you built |
| `wrote_or_taught` | what you wrote or taught |
| `try_tomorrow` | what to try next |
| `created_at` | ISO datetime, set on create |
| `updated_at` | ISO datetime, set on every write |

### 3. Apps Script

> **`date` must be a text column.** It holds a local timestamp with its UTC
> offset — `2026-08-29T14:32:07+05:30`. If Sheets turns that cell into a real
> date, the Apps Script serialises it back as a UTC datetime and every entry
> shows a day early west of Greenwich. The script pins new rows to text
> automatically; entries written before this carry a date with no time and are
> left exactly as they are.

Open the sheet → **Extensions → Apps Script**, replace everything with
[`google-apps-script-v2.js`](./google-apps-script-v2.js), then **Deploy → New
deployment → Web app**, executing as *Me*, access *Anyone*. Run `testSetup`
first to confirm the headers line up. Copy the deployment URL.

### 4. Firebase

1. Create a project at [console.firebase.google.com](https://console.firebase.google.com)
2. Enable **Email/Password** authentication
3. Add your users by hand under Authentication → Users
4. Copy the web app config values

### 5. Environment

Copy `.env.example` to `.env` and fill it in:

```bash
GOOGLE_SHEET_DB_URL=      # the Apps Script deployment URL
FIREBASE_PROJECT_ID=      # used by the proxy to verify tokens

FIREBASE_API_KEY=
FIREBASE_AUTH_DOMAIN=
FIREBASE_STORAGE_BUCKET=
FIREBASE_MESSAGING_SENDER_ID=
FIREBASE_APP_ID=

# The same values, exposed to the Expo client
EXPO_PUBLIC_FIREBASE_API_KEY=
EXPO_PUBLIC_FIREBASE_AUTH_DOMAIN=
EXPO_PUBLIC_FIREBASE_PROJECT_ID=
EXPO_PUBLIC_FIREBASE_STORAGE_BUCKET=
EXPO_PUBLIC_FIREBASE_MESSAGING_SENDER_ID=
EXPO_PUBLIC_FIREBASE_APP_ID=
```

## Running

```bash
npm start          # Expo dev server (choose a platform)
npm run web        # web only
npm run ios
npm run android

npm run server     # local proxy on :3000 — the web app expects this in dev
```

In development the web client posts to `http://localhost:3000/api/proxy`, so
`npm run server` needs to be running alongside `npm run web`.

```bash
npx tsc --noEmit   # typecheck
npm run lint
npm run build:web  # production web bundle into dist/
```

## Deploying

The repo is configured for **Netlify** ([`netlify.toml`](./netlify.toml) plus
the functions in [`netlify/functions/`](./netlify/functions)):

- build `npm run build:web`, publish `dist`, functions `netlify/functions`
- `/api/*` rewrites to the functions, everything else to `index.html`
- set `GOOGLE_SHEET_DB_URL` and `FIREBASE_PROJECT_ID` in the site's environment
  variables, along with the `EXPO_PUBLIC_*` Firebase values

A `vercel.json` and an Express equivalent (`server.js`) are also present from an
earlier deployment and still work, but Netlify is the maintained path.

Android builds go through EAS — see [EAS_BUILD_GUIDE.md](./EAS_BUILD_GUIDE.md).

## Known issues

**Native traffic bypasses the authenticated proxy.** `getApiUrl()` in
`services/research-log-service.ts` sends iOS and Android requests straight to
the Apps Script URL. That deployment is set to "Anyone" and performs no token
verification of its own, so the token the client attaches is never checked on
that path — anyone holding the URL can read and write the whole corpus. Web is
verified at the Netlify function; native is verified nowhere.

Tracked under *Open items* in [docs/DECISIONS.md](docs/DECISIONS.md) and must be
closed before attachments ship.
